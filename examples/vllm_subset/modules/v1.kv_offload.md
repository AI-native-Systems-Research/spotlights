## Findings (full list)

1. **KVPR: Efficient LLM Inference with I/O-Aware KV Cache Partial Recomputation**
   - Source type: paper
   - URL: <https://aclanthology.org/2025.findings-acl.997/>
   - Technique: Use I/O-aware partial recomputation instead of always transferring the full offloaded KV cache before execution. A profiler/scheduler can choose a split where a small activation subset is transferred first, GPU recomputes part of the KV cache, and the remaining KV transfer runs concurrently, reducing CPU-GPU transfer stalls that hurt TTFT/TPOT.
   - Evidence: "While the GPU recomputes the partial KV cache, the remaining portion of the KV cache is transferred concurrently from the CPU. This approach overlaps GPU recomputation with KV cache transfer to minimize idle GPU time and maximize inference performance." Pointer: Abstract, ACL Anthology page lines L5-L6.
2. **KV cache with CPU offloading #30704**
   - Source type: issue
   - URL: <https://github.com/huggingface/transformers/issues/30704>
   - Technique: Adopt a layer-pipelined offload runtime: keep only the active layer and next prefetched layer on GPU, evict the previous layer after attention, and overlap layer compute with CPU-GPU movement. This is a concrete way to reduce peak GPU residency and hide offload latency for long contexts.
   - Evidence: "When we do the forward pass on layer k, we evict layer k-1 and prefetch layer k+1. Thus, there are always at most 2 layers of KV cache in GPU memory." Pointer: issue body, Motivation section, lines L1-L2.
3. **SGLang HiCache: Fast Hierarchical KV Caching with Your Favorite Storage Backends**
   - Source type: blog
   - URL: <https://www.lmsys.org/blog/2025-09-10-sglang-hicache/>
   - Technique: Use a hierarchical KV page table plus cache controller to manage GPU, CPU, and external tiers, and optimize the data plane with GPU-assisted I/O kernels and CPU memory layouts decoupled from GPU layout. For multi-turn agentic workloads, this suggests host offload should optimize both reuse metadata and CPU-GPU transfer layout rather than just maintain an LRU-like block store.
   - Evidence: "Alongside, a cache controller automatically manages loading and backing up KV cache data across hierarchies, including GPU and CPU memory pools as well as external layers such as disks and remote memory." "Beyond the standard cudaMemcpyAsync, we developed a set of GPU-assisted I/O kernels that deliver up to 3× higher throughput for CPU–GPU transfers." Pointer: sections "Why Hierarchical KV Caching Matters" and "Design of SGLang HiCache: Optimized data plane", lines L5-L6.
4. **LMCache: An Efficient KV Cache Layer for Enterprise-Scale LLM Inference**
   - Source type: paper
   - URL: <https://arxiv.org/html/2510.09665v2>
   - Technique: Introduce a first-class KV movement/control plane with batched data movement, compute-I/O pipelining, and explicit operations such as pinning, lookup, cleanup, movement, and compression. The target module could use the same design direction to make CPU offload orchestration more latency-aware and easier to extend beyond basic store/load completion.
   - Evidence: "LMCache ’s high performance and wide adoption stem from the following contributions: (i) highly optimized KV cache data movement powered by batched data movement operations, compute and I/O pipelining; ... (iii) a first-class control API, such as pinning, lookup, cleanup, movement, and compression, for flexible cache orchestration across GPU, CPU, storage, and network layers." Pointer: paper introduction/contributions, lines L2-L3.
5. **CacheGen: KV Cache Compression and Streaming for Fast Large Language Model Serving**
   - Source type: paper
   - URL: <https://arxiv.org/abs/2310.07240>
   - Technique: Compress offloaded KV blocks with a tensor-aware encoder and adapt compression level or recomputation based on available bandwidth. This could reduce host memory footprint and PCIe transfer bytes, improving TTFT when loading long reusable contexts from CPU memory.
   - Evidence: "CacheGen uses a custom tensor encoder, leveraging KV cache's distributional properties to encode a KV cache into more compact bitstream representations with negligible decoding overhead, to save bandwidth usage. Second, CacheGen adapts the compression level of different parts of a KV cache to cope with changes in available bandwidth." Pointer: Abstract, lines L1-L3.
6. **KIVI: A Tuning-Free Asymmetric 2bit Quantization for KV Cache**
   - Source type: paper
   - URL: <https://arxiv.org/abs/2402.02750>
   - Technique: Store offloaded KV in an asymmetric low-bit representation: quantize keys per-channel and values per-token. This could increase CPU offload capacity and reduce CPU-GPU transfer volume while preserving enough precision for reused multi-turn context.
   - Evidence: "Our findings indicate that the key cache should be quantized per-channel, i.e., group elements along the channel dimension and quantize them together. In contrast, the value cache should be quantized per-token." Pointer: Abstract, lines L2-L3.
7. **InfiniGen: Efficient Generative Inference of Large Language Models with Dynamic KV Cache Management**
   - Source type: paper
   - URL: <https://arxiv.org/abs/2406.19707>
   - Technique: Use a lightweight rehearsal to predict which KV entries will matter and prefetch only those entries from host memory. The offload layer could adapt this as block-level speculative prefetch/admission to avoid loading or reserving bandwidth for cold KV blocks during long-generation or agentic sessions.
   - Evidence: "This allows us to prefetch only the essential KV cache entries (without fetching them all), thereby mitigating the fetch overhead from the host memory in offloading-based LLM serving systems." Pointer: Abstract, lines L1-L2.
8. **FIFO Queues are All You Need for Cache Eviction**
   - Source type: paper
   - URL: <https://jasony.me/publication/sosp23-s3fifo.pdf>
   - Technique: Replace or augment LRU/ARC policy with S3-FIFO: a small probationary FIFO filters one-hit entries before they enter the main cache. This directly targets multi-turn workloads with long scans and many one-off blocks, reducing CPU offload churn and preserving reusable prefixes.
   - Evidence: "The key of S3-FIFO is a small FIFO queue that filters out most objects from entering the main cache, which provides a guaranteed demotion speed and high demotion precision." Pointer: Abstract/Introduction, lines L1-L2.
9. **TinyLFU: A Highly Efficient Cache Admission Policy**
   - Source type: paper
   - URL: <https://arxiv.org/pdf/1512.00727>
   - Technique: Use TinyLFU-style admission: compare a new block against the eviction candidate using approximate recent frequency rather than admitting every stored block after a fixed threshold. This could reduce useless CPU stores and improve offload hit rate for skewed repeated agent contexts.
   - Evidence: "Given a newly accessed item and an eviction candidate from the cache, our scheme decides, based on the recent access history, whether it is worth admitting the new item into the cache at the expense of the eviction candidate." Pointer: Abstract, lines L12-L14.
10. **GreedyDual-Size Algorithm**
   - Source type: paper
   - URL: <https://www.usenix.org/legacy/publications/library/proceedings/usits97/full_papers/cao/cao_html/node8.html>
   - Technique: Use cost/size-aware eviction where each cached block’s value reflects miss cost divided by bytes. For KV offload, the cost can be estimated from recompute latency or transfer time, helping the manager keep blocks that save the most TTFT/TPOT per unit of CPU memory or PCIe bandwidth.
   - Evidence: "To incorporate the difference sizes of the document, we extend the GreedyDual algorithm by setting H to cost / size upon an access to a document, where cost is the cost of bringing the document, and size is the size of the document in bytes." Pointer: algorithm description, lines L3-L5.
11. **SIEVE is Simpler than LRU: an Efficient Turn-Key Eviction Algorithm for Web Caches**
   - Source type: paper
   - URL: <https://www.usenix.org/conference/nsdi24/presentation/zhang-yazhuo>
   - Technique: Consider a SIEVE-style eviction primitive for low-overhead cache policy decisions: a queue plus visited bit avoids per-hit promotion work while retaining strong miss-ratio behavior. This could lower scheduler-side policy overhead and make larger CPU offload indexes cheaper to maintain.
   - Evidence: "This work presents SIEVE, an algorithm that is simpler than LRU and provides better than state-of-the-art efficiency and scalability for web cache workloads." "SIEVE's simplicity comes with superior scalability as cache hits require no locking." Pointer: USENIX abstract, lines L1-L3.
