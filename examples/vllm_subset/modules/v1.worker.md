## Findings (full list)

1. **RServe: Overlapping Encoding and Prefill for Efficient LMM Inference**
   - Source type: paper
   - URL: <https://arxiv.org/html/2509.24381v1>
   - Technique: Use fine-grained intra-request pipelining so multimodal encoding can overlap with language-model prefill, and use token budgets to balance inter-request micro-batches. This directly targets media TTFT by avoiding a strictly serial encode-then-prefill path while keeping worker execution balanced.
   - Evidence: Quote: "RServe adopts a fine-grained scheduling method that overlaps multimodal encoding with the forward computation of the language model within a single request. For inter-request pipeline, RServe leverages schedulable tokens and token budgets to balance computational loads across micro-batches." Pointer: Abstract, arXiv HTML lines L3-L4.
2. **Efficiently Serving Large Multimodal Models Using EPD Disaggregation**
   - Source type: paper
   - URL: <https://arxiv.org/html/2501.05460v2>
   - Technique: Separate encode, prefill, and decode into dedicated worker roles, then add multimedia-token caching, intra-request encoding parallelism, resource allocation, and role switching. This could reduce media TTFT by isolating heavy encoders from decode workers and reduce median TPOT by preventing encode/prefill interference.
   - Evidence: Quote: "We introduce Encode-Prefill-Decode (EPD) Disaggregation, a novel framework that separates the encoding, prefill, and decode stages onto dedicated resources." "These include a new mechanism to cache multimedia tokens for efficient transfer, a novel way to parallelize encoding load within a request..." Pointer: Abstract, arXiv HTML lines L1-L2.
3. **SparseVLM: Visual Token Sparsification for Efficient Vision-Language Model Inference**
   - Source type: paper
   - URL: <https://arxiv.org/html/2410.04417>
   - Technique: Apply training-free, text-guided visual token sparsification using decoder self-attention to rank visual token importance, with adaptive layer-wise sparsification and token recycling. This can shorten multimodal prefill and reduce downstream decode KV/cache pressure for media-heavy agent turns.
   - Evidence: Quote: "we select relevant text tokens to rate the significance of visual tokens using self-attention matrices and, then, prune visual tokens using the proposed strategy to maximize sparsity while retaining information." Pointer: Abstract, arXiv HTML.
4. **MMInference: Accelerating Pre-filling for Long-Context VLMs via Modality-Aware Permutation Sparse Attention**
   - Source type: paper
   - URL: <https://arxiv.org/html/2504.16083v1>
   - Technique: Use modality-aware permutation sparse attention for long-context VLM prefill, including grid-shaped sparse patterns for video and explicit handling of modality boundaries. This is a concrete path for lowering media TTFT when image/video tokens dominate prefill cost.
   - Evidence: Quote: "First, our analysis reveals that the temporal and spatial locality of video input leads to a unique sparse pattern, the Grid pattern. Simultaneously, VLMs exhibit markedly different sparse distributions across different modalities." Pointer: Abstract, arXiv HTML.
5. **TokenWeave: Efficient Compute-Communication Overlap for Distributed LLM Inference**
   - Source type: paper
   - URL: <https://arxiv.org/pdf/2505.11329v4>
   - Technique: Split tokens into two wave-aware subsets so communication for one subset overlaps computation for the other, and fuse AllReduce with RMSNorm using a small SM budget. This could improve median TPOT for tensor-parallel workers by making micro-batching communication-aware rather than only batch-slice-aware.
   - Evidence: Quote: "TokenWeave proposes a Token-Splitting technique that divides the tokens in the inference batch into two approximately equal subsets in a wave-aware manner. The communication of one subset is then overlapped with the computation of the other." Pointer: Abstract, PDF lines L2-L3.
6. **NanoFlow: Towards Optimal Large Language Model Serving Throughput**
   - Source type: paper
   - URL: <https://arxiv.org/html/2408.12757v2>
   - Technique: Use intra-device nano-batching and operation-level scheduling to overlap compute, memory, and networking work inside one device. This offers a more general form of worker-side ubatching that could reduce TPOT by tuning slice size, ordering, and resource allocation instead of using fixed micro-batch structure.
   - Evidence: Quote: "NanoFlow splits inputs into smaller nano-batches and duplicates operations to operate on each portion independently, enabling overlapping. NanoFlow automatically identifies the number, size, ordering, and GPU resource allocation of nano-batches to minimize the execution time..." Pointer: Abstract, arXiv HTML lines L4-L5.
7. **Taming Throughput-Latency Tradeoff in LLM Inference with Sarathi-Serve**
   - Source type: paper
   - URL: <https://arxiv.org/html/2403.02310v1>
   - Technique: Use chunked-prefills and decode-maximal batching to create stall-free mixed prefill/decode iterations. The worker-side adaptation is to shape mixed input batches and micro-batches so long prefills, including media-heavy ones, do not pause ongoing decode progress and inflate median TPOT.
   - Evidence: Quote: "Sarathi-Serve leverages chunked-prefills from Sarathi to create stall-free schedules that can add new requests in a batch without pausing ongoing decodes." Pointer: Abstract, arXiv HTML line L4.
8. **BatchLLM: Optimizing Large Batched LLM Inference with Global Prefix Sharing and Throughput-oriented Token Batching**
   - Source type: paper
   - URL: <https://arxiv.org/pdf/2412.03594>
   - Technique: Exploit global prefix sharing, prefix-aware request grouping, memory-centric token batching, and attention kernel optimization. This could help multi-turn agentic workloads where many requests share system/tool prefixes by reducing repeated prefill work and improving batch utilization.
   - Evidence: Quote: "BatchLLM explicitly identifies the common prefixes globally. The requests sharing the same prefix will be scheduled together to reuse the KV context the best." Pointer: Abstract, arXiv PDF first page.
9. **CacheBlend: Fast Large Language Model Serving for RAG with Cached Knowledge Fusion**
   - Source type: paper
   - URL: <https://arxiv.org/html/2405.16444v3>
   - Technique: Fuse multiple precomputed KV caches even when reused chunks are not prefixes, then selectively recompute a small token subset and pipeline that recompute with KV retrieval. This is useful for agentic/RAG turns where repeated context chunks appear in different positions and ordinary prefix caching leaves TTFT on the table.
   - Evidence: Quote: "We present CacheBlend, a scheme that reuses the pre-computed KV caches, regardless prefix or not, and selectively recomputes the KV values of a small subset of tokens to partially update each reused KV cache." Pointer: Abstract, arXiv HTML lines L3-L4.
10. **CacheGen: KV Cache Compression and Streaming for Fast Large Language Model Serving**
   - Source type: paper
   - URL: <https://arxiv.org/abs/2310.07240>
   - Technique: Compress KV caches into compact bitstreams using KV distribution properties, then adapt compression levels to available bandwidth. This could reduce TTFT for reused long/media contexts and disaggregated workers by making KV or encoder-cache transfer less bandwidth-bound.
   - Evidence: Quote: "CacheGen uses a custom tensor encoder, leveraging KV cache's distributional properties to encode a KV cache into more compact bitstream representations with negligible decoding overhead, to save bandwidth usage." Pointer: Abstract, arXiv abstract lines L1-L2.
11. **KVPR: Efficient LLM Inference with I/O-Aware KV Cache Partial Recomputation**
   - Source type: paper
   - URL: <https://arxiv.org/html/2411.17089v2>
   - Technique: Transfer a partial activation set first so the GPU can recompute part of the KV cache while the remaining KV cache transfers asynchronously. This could lower TPOT for offloaded or remote KV paths by turning KV load time into overlapped compute rather than idle wait.
   - Evidence: Quote: "While the GPU recomputes the partial KV cache, the remaining portion of the KV cache is transferred concurrently from the CPU. This approach overlaps GPU recomputation with KV cache transfer to minimize idle GPU time and maximize inference performance." Pointer: Abstract, arXiv HTML lines L4-L5.
12. **Quest: Query-Aware Sparsity for Efficient Long-Context LLM Inference**
   - Source type: paper
   - URL: <https://arxiv.org/abs/2406.10774>
   - Technique: Track min/max key summaries per KV page and use the current query to load only the top-K critical KV pages for attention. This could reduce long-context TPOT by decreasing KV memory movement during decode without permanently evicting cache entries.
   - Evidence: Quote: "Quest keeps track of the minimal and maximal Key values in KV cache pages and estimates the criticality of a given page using Query vectors. By only loading the Top-K critical KV cache pages for attention, Quest significantly speeds up self-attention without sacrificing accuracy." Pointer: Abstract, arXiv abstract lines L1-L2.
13. **Flash-Decoding for long-context inference - PyTorch**
   - Source type: blog
   - URL: <https://pytorch.org/blog/flash-decoding/>
   - Technique: Parallelize decode attention over the KV length by splitting keys/values, loading them in parallel, then rescaling and combining partial attention results. This targets median TPOT for long multi-turn contexts where each decode step is dominated by reading a large KV cache.
   - Evidence: Quote: "The main idea is to load the keys and values in parallel as fast as possible, then separately rescale and combine the results to maintain the right attention outputs." Pointer: PyTorch blog introduction.
14. **LayerSkip: Enabling Early Exit Inference and Self-Speculative Decoding**
   - Source type: paper
   - URL: <https://aclanthology.org/2024.acl-long.681/>
   - Technique: Use early-exit layers to draft tokens and verify/correct them with the remaining layers of the same model, sharing compute and activations instead of running a separate draft model. This could reduce TPOT for supported models while keeping memory pressure lower than multi-model speculative decoding.
   - Evidence: Quote: "Third, we present a novel self-speculative decoding solution where we exit at early layers and verify and correct with remaining layers of the model." Pointer: Abstract, ACL Anthology page.
15. **Sequoia: Scalable, Robust, and Hardware-aware Speculative Decoding**
   - Source type: paper
   - URL: <https://arxiv.org/pdf/2402.12374>
   - Technique: Choose speculative decoding token-tree shapes with a hardware-aware dynamic programming algorithm instead of fixed-width or hand-tuned trees. This could improve worker-side speculative decoding by matching verification batch shape to GPU and acceptance-rate characteristics, lowering TPOT.
   - Evidence: Quote: "To improve scalability, SEQUOIA introduces a dynamic programming algorithm to find an optimal tree structure for the speculated tokens." Pointer: Abstract, arXiv PDF.
16. **CUDAGraph Trees - PyTorch 2.12 documentation**
   - Source type: docs
   - URL: <https://docs.pytorch.org/docs/2.12/user_guide/torch_compiler/torch.compiler_cudagraph_trees.html>
   - Technique: Use CUDA graph trees to share one memory pool across many captured graph paths rather than treating each dynamic branch/shape as an isolated capture. This could reduce CUDA graph memory overhead and make graph replay more useful for diverse worker batch shapes common in agentic serving.
   - Evidence: Quote: "Like Graph Callables, CUDA Graph Trees use a single memory pool across all graph captures. However, instead of requiring a single sequence of invocations, CUDA Graph Trees create separate trees of CUDA Graph captures." Pointer: PyTorch documentation, CUDAGraph Trees Integration section.
