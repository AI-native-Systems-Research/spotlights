## Findings (full list)

1. **POD-Attention: Unlocking Full Prefill-Decode Overlap for Faster LLM Inference**
   - Source type: paper
   - URL: <https://arxiv.org/abs/2410.18038>
   - Technique: Adopt or expose a fused hybrid-batch attention path that runs prefill and decode work concurrently instead of dispatching independently specialized kernels. This directly targets mixed multi-turn serving, where prefill TTFT and decode TPOT compete in the same batch.
   - Evidence: Quote: "prefill and decode operations happen concurrently on the same multiprocessor". Pointer: abstract, arXiv page lines 1-2.
2. **Hydragen: High-Throughput LLM Inference with Shared Prefixes**
   - Source type: paper
   - URL: <https://arxiv.org/abs/2402.05099>
   - Technique: Generalize shared-prefix attention beyond a single batch-wide common prefix by decomposing attention into shared-prefix and unique-suffix components, including hierarchical/tree sharing. This fits multi-turn agentic workloads with repeated system prompts, tool schemas, and branch-like continuations, reducing redundant KV reads during TTFT and decode.
   - Evidence: Quote: "computes attention over the shared prefix and unique suffixes separately". Pointer: abstract, arXiv page lines 2-4.
3. **MMInference: Accelerating Pre-filling for Long-Context Visual Language Models via Modality-Aware Permutation Sparse Attention**
   - Source type: paper
   - URL: <https://proceedings.mlr.press/v267/li25aq.html>
   - Technique: Add a media-aware sparse prefill option that recognizes video/image token locality, permutes tokens to expose grid-like sparsity, and chooses head-specific sparse patterns offline. This is directly aligned with reducing media TTFT for long multimodal prompts without changing model weights.
   - Evidence: Quote: "permutation-based method to leverage the unique Grid pattern and handle modality boundary issues". Pointer: PMLR abstract, lines 2-4.
4. **FlashInfer: Efficient and Customizable Attention Engine for LLM Inference Serving**
   - Source type: paper
   - URL: <https://openreview.net/forum?id=RXPofAsL8F>
   - Technique: Use block-sparse/composable KV formats plus load-balanced scheduling as first-class backend policy, not only as fixed wrapper calls. This could reduce metadata and kernel inefficiency for dynamic agent batches while preserving CUDA Graph compatibility for low TPOT.
   - Evidence: Quote: "load-balanced scheduling algorithm adjusts to dynamism of user requests while maintaining compatibility with CUDAGraph". Pointer: OpenReview abstract, lines 1-3.
5. **Flash-Decoding for long-context inference – PyTorch Blog**
   - Source type: blog
   - URL: <https://pytorch.org/blog/flash-decoding/>
   - Technique: Make split-KV decode more adaptive by parallelizing over KV sequence length and merging partial outputs with log-sum-exp state. This is useful when long multi-turn contexts and small effective batch sizes leave decode kernels under-occupying the GPU.
   - Evidence: Quote: "adds a new parallelization dimension: the keys/values sequence length". Pointer: PyTorch blog, "A faster attention for decoding" discussion and lines 4-7.
6. **QUEST: Query-Aware Sparsity for Efficient Long-Context LLM Inference**
   - Source type: paper
   - URL: <https://proceedings.mlr.press/v235/tang24l.html>
   - Technique: Introduce an optional query-aware sparse decode path that ranks KV-cache pages from per-page key min/max metadata and loads only the top pages. This targets median TPOT in long-context agent turns by reducing memory traffic in paged attention.
   - Evidence: Quote: "only loading the Top-K critical KV cache pages for attention". Pointer: PMLR abstract, lines 1-2.
7. **MInference 1.0: Accelerating Pre-filling for Long-Context LLMs via Dynamic Sparse Attention**
   - Source type: paper
   - URL: <https://arxiv.org/abs/2407.02490>
   - Technique: Use head-specific offline sparse-pattern selection with online sparse-index construction for long prefill attention. This could lower TTFT for large text or tool-history prompts by routing compatible heads to optimized sparse prefill kernels.
   - Evidence: Quote: "determine the optimal pattern for each attention head offline". Pointer: arXiv abstract, lines 3-5.
8. **FlashDecoding++: Faster Large Language Model Inference with Asynchronization, Flat GEMM Optimization, and Heuristics**
   - Source type: paper
   - URL: <https://proceedings.mlsys.org/paper_files/paper/2024/hash/5321b1dabcd2be188d796c21b733e8c7-Abstract-Conference.html>
   - Technique: Apply asynchronous partial-softmax merging, double-buffered flat GEMM handling, and hardware-adaptive dataflow choices to custom decode kernels. These techniques map to the module’s split/segmented decode paths and can reduce synchronization and shape-specific underutilization.
   - Evidence: Quote: "unified max value technique for different partial softmax computations to avoid synchronization". Pointer: MLSys abstract, lines 1-5.
9. **New XQA-kernel provides 2.4x more Llama-70B throughput within the same latency budget**
   - Source type: blog
   - URL: <https://github.com/NVIDIA/TensorRT-LLM/blob/main/docs/source/blogs/XQA-kernel.md>
   - Technique: Prefer or specialize TensorRT-LLM XQA-style generation kernels for MQA/GQA decode when model shape, hardware, and KV layout match. This can reduce TPOT for common grouped-query models by using tensor cores and avoiding unnecessary data movement/conversion.
   - Evidence: Quote: "optimization for MQA and GQA during generation phase". Pointer: TensorRT-LLM blog source, lines 0-2.
10. **FlexAttention + FlashAttention-4: Fast and Flexible – PyTorch**
   - Source type: blog
   - URL: <https://pytorch.org/blog/flexattention-flashattention-4-fast-and-flexible/>
   - Technique: Use FlexAttention’s FA4 backend as a route for custom score/mask variants such as sliding window, soft-capping, document/media prefix masks, or combinations that otherwise require bespoke kernels. This could improve feature coverage without falling back to slower generic attention for uncommon but agent/media-relevant masks.
   - Evidence: Quote: "JIT-instantiate FlashAttention-4 for custom attention variants". Pointer: PyTorch blog TL;DR, lines 0-2.
11. **KIVI: A Tuning-Free Asymmetric 2bit Quantization for KV Cache**
   - Source type: paper
   - URL: <https://proceedings.mlr.press/v235/liu24bz.html>
   - Technique: Add asymmetric low-bit KV-cache support with per-channel key quantization and per-token value quantization. This targets decode TPOT by lowering KV bandwidth and allowing larger resident batches for long multi-turn contexts.
   - Evidence: Quote: "key cache should be quantized per-channel" and "value cache should be quantized per-token". Pointer: PMLR abstract, lines 1-4.
12. **KVQuant: Towards 10 Million Context Length LLM Inference with KV Cache Quantization**
   - Source type: paper
   - URL: <https://proceedings.neurips.cc/paper_files/paper/2024/hash/028fcbcf85435d39a40c4d61b42c99a4-Abstract-Conference.html>
   - Technique: Explore pre-RoPE key quantization, non-uniform KV datatypes, and dense-sparse outlier handling as lower-bit alternatives to current KV-cache formats. These are attention-backend-relevant because they require fused cache update/dequantization kernels and can reduce long-context TPOT.
   - Evidence: Quote: "Pre-RoPE Key Quantization" and "Non-Uniform KV Cache Quantization". Pointer: NeurIPS abstract, lines 2-5.
13. **Cascade and Recursive Attention | flashinfer-ai/flashinfer | DeepWiki**
   - Source type: other
   - URL: <https://deepwiki.com/flashinfer-ai/flashinfer/2.4-cascade-and-recursive-attention>
   - Technique: Use recursive attention states with associative log-sum-exp merging to repair or extend cascade execution over multiple KV subsets. This gives an implementation model for shared-prefix, hierarchical cache, and KV-sequence-parallel attention without sacrificing exactness.
   - Evidence: Quote: "attention over disjoint index subsets, computed independently, then merged". Pointer: overview, lines 0-2.
