## Findings (full list)

1. **Efficiently Serving Large Multimodal Models Using EPD Disaggregation**
   - Source type: paper
   - URL: <https://arxiv.org/html/2501.05460v2>
   - Technique: Encode-Prefill-Decode disaggregation separates multimodal encoding from prefill and decode, adds multimedia-token caching, and parallelizes encoding within a request. The target module could adapt its encoder scheduling and cache admission to reduce media TTFT by avoiding encoder-prefill interference and by making repeated media cheap to serve.
   - Evidence: Quote: "We introduce Encode-Prefill-Decode (EPD) Disaggregation, a novel framework that separates the encoding, prefill, and decode stages onto dedicated resources." Pointer: Abstract, lines 1-2.
2. **Continuum: Efficient and Robust Multi-Turn LLM Agent Scheduling with KV Cache Time-to-Live**
   - Source type: paper
   - URL: <https://arxiv.org/abs/2511.02230>
   - Technique: CacheTTL selectively pins KV cache for tool-call turns using a time-to-live derived from reload/recompute cost and queueing impact. For multi-turn agentic workloads, this could preserve hot conversation state across short tool pauses, reducing repeated prefill TTFT without permanently occupying GPU memory.
   - Evidence: Quote: "For requests that generate tool calls, CacheTTL selectively pins the KV cache in GPU memory with a time-to-live value determined by the reload cost and potential queueing delay induced by eviction." Pointer: Abstract, line 3.
3. **KVFlow: Efficient Prefix Caching for Accelerating LLM-Based Multi-Agent Workflows**
   - Source type: paper
   - URL: <https://arxiv.org/abs/2507.07400>
   - Technique: KVFlow replaces plain LRU prefix-cache eviction with workflow-aware eviction and overlapped CPU-to-GPU prefetch based on an Agent Step Graph. The module could use future agent-step metadata, when available, to protect and prefetch likely-next prefixes, improving agentic TTFT and reducing cache-miss stalls.
   - Evidence: Quote: "KVFlow abstracts the agent execution schedule as an Agent Step Graph and assigns each agent a steps-to-execution value that estimates its temporal proximity to future activation." Pointer: Abstract, line 2.
4. **Efficiently Programming Large Language Models using SGLang**
   - Source type: paper
   - URL: <https://arxiv.org/html/2312.07104v1>
   - Technique: RadixAttention stores reusable KV state in a radix tree and uses cache-aware scheduling by matched-prefix length. The module could adapt this idea by ranking waiting requests by resident-prefix benefit, increasing prefix-hit rates for multi-call agent and chat workloads instead of relying only on arrival or static priority.
   - Evidence: Quote: "we propose RadixAttention, a novel technique that maintains a Least Recently Used (LRU) cache of the Key-Value (KV) cache for all requests in a radix tree". Pointer: Abstract, line 3; cache-aware scheduling is described in Algorithm 1.
5. **LLM Query Scheduling with Prefix Reuse and Latency Constraints**
   - Source type: paper
   - URL: <https://openreview.net/forum?id=HKfZwLjSwQ>
   - Technique: The k-LPM scheduler balances longest-prefix-match reuse with fairness under TTFT/TPOT constraints. This gives the module a concrete way to avoid the extremes of FCFS and pure cache-hit prioritization when optimizing median latency for prefix-heavy traffic.
   - Evidence: Quote: "we present a formal theoretical framework for LLM query scheduling under RadixAttention" and propose "$k$-LPM, which generalizes existing methods by balancing prefix reuse and fairness". Pointer: Abstract, lines 2-3.
6. **Optimal Scheduling Algorithms for LLM Inference: Theory and Practice**
   - Source type: paper
   - URL: <https://arxiv.org/abs/2508.01002>
   - Technique: SLAI uses real-time decode deadline measurements and prompt-length-aware prefill reordering. The module could incorporate deadline/laxity and prompt length into token-budget allocation to lower median TTFT while protecting TPOT.
   - Evidence: Quote: "SLAI uses real-time measurements to prioritize decode requests that are close to missing their TBT deadlines and reorders prefill requests based on known prompt lengths". Pointer: Abstract, line 3.
7. **Taming Throughput-Latency Tradeoff in LLM Inference with Sarathi-Serve**
   - Source type: paper
   - URL: <https://arxiv.org/abs/2403.02310>
   - Technique: Sarathi-Serve splits long prefills into near-equal chunks and builds stall-free schedules that add prefills without pausing decodes. The module could make chunk sizing and prefill/decode interleaving more adaptive to reduce median TPOT without letting long media or tool prompts dominate a scheduling step.
   - Evidence: Quote: "Sarathi-Serve introduces chunked-prefills which splits a prefill request into near equal sized chunks and creates stall-free schedules that adds new requests in a batch without pausing ongoing decodes." Pointer: Abstract, line 3.
8. **Introducing New KV Cache Reuse Optimizations in NVIDIA TensorRT-LLM**
   - Source type: blog
   - URL: <https://developer.nvidia.com/blog/introducing-new-kv-cache-reuse-optimizations-in-nvidia-tensorrt-llm/>
   - Technique: TensorRT-LLM adds priority-based KV eviction with retention priority and duration per token range. The module could extend LRU block eviction with priority/TTL hints for system prompts, agent role prompts, media-derived prefixes, and active sessions that are likely to be reused.
   - Evidence: Quote: "Priority-based eviction is a new feature of the TensorRT-LLM Executor API that enables users to influence how blocks are selected for eviction." Pointer: section "Priority-based KV cache eviction", lines 4-5.
9. **AttentionStore: Cost-effective Attention Reuse across Multi-turn Conversations in Large Language Model Serving**
   - Source type: paper
   - URL: <https://arxiv.org/html/2403.19708v2>
   - Technique: AttentionStore keeps KV caches in a hierarchy of GPU/host/storage tiers and uses scheduler-aware fetch/eviction plus asynchronous layer-wise preload/save. The module could use scheduler hints to decide which remote or lower-tier KV blocks to fetch early and which local blocks to demote, reducing multi-turn TTFT.
   - Evidence: Quote: "AttentionStore employs layer-wise pre-loading and asynchronous saving schemes to overlap the KV cache access with the GPU computation." Pointer: Abstract, line 4.
10. **CacheGen: Fast Context Loading for Language Model Applications via KV Cache Streaming**

   - Technique: CacheGen compresses KV tensors into compact bitstreams and adapts compression versus recomputation based on bandwidth. For remote KV loading paths, the module could schedule compressed transfer or recomputation per block to minimize context-loading TTFT under variable network conditions.
   - Evidence: Quote: "When available bandwidth drops, CacheGen may raise the compression level for a part of the context or choose to recompute its KV cache on the fly." Pointer: publication summary, line 3.

   - Evidence: Quote: "The core of Mooncake is its KVCache-centric scheduler, which balances maximizing overall effective throughput while meeting latency-related Service Level Objectives (SLOs)." Pointer: Abstract, line 1.

The module could use its local scheduling and KV-transfer decisions to better isolate prefill-heavy media or long-context work from decode-heavy traffic.
   - Evidence: Quote: "DistServe assigns prefill and decoding computation to different GPUs, hence eliminating prefill-decoding interferences." Pointer: Abstract, line 2.
13. **VLCache: Computing 2% Vision Tokens and Reusing 98% for Vision-Language Inference**
   - Source type: paper
   - URL: <https://arxiv.org/pdf/2512.12977>
   - Technique: VLCache reuses both encoder cache and KV cache for recurring multimodal inputs, then recomputes only a small, layer-aware subset of vision tokens to control reuse error. This could guide media-cache reuse policies beyond exact prefix hits, reducing media TTFT for repeated images or visual context across agent turns.
   - Evidence: Quote: "VLCache achieves an accuracy on par with full recomputation, while requiring only 2-5% of the tokens to compute, yielding 1.2x-16x TTFT speedups." Pointer: Abstract, line 2.
14. **Embedding Cache**
   - Source type: docs
   - URL: <https://docs.dynamo.nvidia.com/dynamo/user-guides/multimodal/embedding-cache>
   - Technique: NVIDIA Dynamo uses a CPU-side LRU cache of vision encoder outputs owned by the prefill worker; on hit, it skips the encode worker entirely, and on miss it transfers embeddings via NIXL and stores them. The module could adapt this as a host-tier encoder cache policy for repeated media, reducing GPU encoder load and media TTFT.
   - Evidence: Quote: "On a hit, the encode worker is skipped entirely. On a miss, the encode worker produces the embedding, transfers it via NIXL, and the prefill worker saves it to the cache." Pointer: How It Works, lines 3-4.
15. **ChunkAttention: Efficient Self-Attention with Prefix-Aware KV Cache and Two-Phase Partition**
   - Source type: paper
   - URL: <https://aclanthology.org/2024.acl-long.623/>
   - Technique: ChunkAttention chunks KV tensors into an auxiliary prefix tree and uses a two-phase partition algorithm to improve locality when many requests share system prompts. The module could schedule prefix-similar requests together and expose richer common-prefix information to downstream attention execution to improve TPOT for shared-prefix batches.
   - Evidence: Quote: "This is achieved by breaking monolithic key/value tensors into smaller chunks and structuring them into the auxiliary prefix tree." Pointer: Abstract, line 4.
16. **CacheBlend: Fast Large Language Model Serving for RAG with Cached Knowledge Fusion**
   - Source type: paper
   - URL: <https://www.microsoft.com/en-us/research/publication/you-only-prefill-once-combining-cached-knowledge-for-large-language-model-serving-with-cacheblend/>
   - Technique: CacheBlend reuses precomputed KV caches for text chunks even when they are not prompt prefixes, selectively recomputing a small token subset to recover quality. The module could generalize cache lookup and admission beyond strict leading-prefix reuse for repeated tool/RAG context chunks, lowering TTFT in agentic retrieval-heavy workloads.
   - Evidence: Quote: "We present CacheBlend, a scheme that reuses the pre-computed KV caches, regardless prefix or not, and selectively recomputes the KV values of a small subset of tokens". Pointer: Microsoft Research publication summary.

   - Evidence: Quote: "Pensieve maintains the conversation state across requests by caching previously processed history to avoid duplicate processing." Pointer: Abstract, line 2.
