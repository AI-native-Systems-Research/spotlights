## ⚠️ The evaluation gap — you must define the pass condition

This campaign is **launchable but unscored**. `campaign.yaml` names the
metric and which way it should move, but `ground_truth.pass_condition` is a
`TODO`. Nous will run and report numbers; nothing decides whether
those numbers count as a win until you write that rule.

What Spotlights believes the oracle is:

- **Correctness:** pytest tests/v1/worker/test_gpu_model_runner.py, pytest tests/v1/streaming_input/test_gpu_model_runner_streaming.py
- **Performance:** TTFT, TPOT
- **Direction:** minimize

Replace the `pass_condition` TODO under `ground_truth` in `campaign.yaml`
before trusting any result. Spotlights knows the metric and its direction, not
how much movement counts as a win. A concrete rule for this candidate looks
like:

```yaml
ground_truth:
  pass_condition: >-
    every one of TTFT, TPOT decreases by at least 5% versus the seed baseline,
    with all correctness checks passing
```

Choose the threshold from your own benchmark's noise floor.
