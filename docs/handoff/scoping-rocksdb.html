The question

“What will this cost, and which settings should I use?”

Spotlights reads a codebase and proposes performance findings. It is a five-step pipeline of agent calls, and a full run on a large repository costs real money and most of a working day. Every engineer who has been handed the tool asks the same two questions before they start, and until now the honest answer was a shrug.

The advisor answers them from 18 historical runs across 8 repositories. It does not work by predicting a number. It works by ranking the settings you can change, showing what each is worth relative to the default, and labelling how firmly each of those figures is established.

Scope

What goes in

The only input is the module count. RocksDB's tree yields 29 modules; the run we have on record kept 8 of them — the storage engine's hot path, and about half the repository's code.

Two rows are worth reading twice. Capping findings at 20 does nothing — the observed yield is 14 findings per candidate, already under the cap, so the knob is inert until you push it below the natural yield. And --no-review saves only 14%, which is far less than people assume when they hear that review triples a step.

Provenance

Every number carries its receipt

The labels are not decoration. They are the reason the tool can be trusted where it is strong and discounted where it is weak, and they form a real ladder from arithmetic fact down to educated guess.

exact

A table lookup with no error at all. Switching models changes the price by a known ratio.

measured

Observed directly, on real runs, with the setting as the only difference. Skipping deep research is the one lever with a clean A/B behind it.

derived

Arithmetic on measured inputs. --no-review sits here: review was measured to multiply the 17% discovery step by 2.64× while growing the candidate count only 1.05×, and the 0.86× falls out of those two figures.

unvalidated

Direction is known, magnitude is a guess. Only one row is left in this state, and it is labelled so nobody plans around it.

Until recently --no-review was also unvalidated, because no historical run recorded whether review was on. It turned out to be recoverable from the telemetry — the number of discovery passes per module gives it away exactly — which moved the row up a rung and removed the need for a paid experiment.

The honest test

Where it gets RocksDB wrong

The recorded run cost 276.0M tokens. Compare that against what the advisor would have told you, and the distinction that matters becomes visible.

Read the top bar with suspicion

As shipped, the actual cost lands exactly on the edge of the band — which looks like a triumph and is nearly meaningless. RocksDB is the most expensive repository in the corpus at 34.5M tokens per module, so it is the value that sets that edge. The band contains the run because the run helped draw it.

The lower bar is the real test. With RocksDB held out, the advisor predicts 25–113M tokens with a midpoint of 53M. The truth was 276M — 2.4× above the top of the band, an 81% error on the midpoint. Doing this for all 12 held-out runs gives 58% coverage on the narrow band and 83% on the widest one, with a median error of 80%.

This is not a bug to be fixed by better modelling. Tokens per module spans 23× across repositories, so the module count — the only input — simply cannot narrow it. A five-run replicate test puts the floor at 7.7% variation even when nothing changes. The advisor is built to say so out loud rather than quote a tidy figure it cannot support.

Recommendation

What to actually do with RocksDB

  1. Set the ceiling first.

    Run with --max-cost 308. The engine enforces it and stops. This is the only number on the page that is a promise rather than an estimate, and it makes the width of the band survivable.

  2. Buy information cheaply before buying depth.

    Start with --no-deep-research — roughly $34–$52 and under an hour of wall clock. You see the candidate quality for a third of the price, then re-run the full pipeline on only the modules that looked worthwhile.

  3. Leave the findings cap alone; consider dropping review.

    At 20 the cap is inert. --no-review is a real 14% saving but it costs you candidate quality, and on this evidence that is a poor trade unless you are cost-bound.

  4. Expect the clock, not just the bill.

    The recorded run took 9.3 hours of wall clock against 30.8 hours of API time — only 3.3× effective concurrency. Concurrency is yours to choose, and the corpus has run as high as 13.6×.

For reference, the recorded run produced 109 candidates and 1,137 candidate–finding pairs across all 8 modules, with no module coming up empty.

Reproduce

Running it yourself

The advisor is a single script over a committed calibration snapshot. It makes no API calls and costs nothing to run.

$ python scripts/advisor.py --modules 8

SPOTLIGHTS SCOPING ADVISOR
  in-scope modules      8
  models                claude=claude-opus-5  codex=codex
  token mix             87% cache read, 10% cache write, 2% input, 1% output
  blended list price    $1.12 / MTok
  blended contracted    $0.85 / MTok
  calibration: 18 runs / 8 repos / 6 engine versions

The calibration stores tokens, never dollars — pricing is a rate-table lookup applied at estimate time, so a contract change does not invalidate the history. Pass --exclude to model dropping modules, --claude-model / --codex-model to reprice, and --band p10p90 for the narrower band if you are willing to accept 58% coverage.

Calibration: 18 runs, 8 repositories, 6 engine versions. Bands are the observed min–max spread, backtested leave-one-repository-out at 83% coverage. Figures on this page are drawn from artifacts/advisor_calibration.json and the RocksDB run at commit abeebd9630.
