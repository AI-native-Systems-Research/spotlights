# `_review-notes/`

Point-in-time audits and process artifacts. **Do not read as reference docs.**

These files quote source documents at a specific moment and go stale as the source evolves. They captured useful signal during a review pass; the *conclusions* should already have been folded into the live docs (or filed as open questions there). The audit itself is kept around only so the rationale behind a specific decision can be traced later.

**When to read a file in this folder:** you're tracing the history of a decision and want to see what the reviewer was reacting to.

**When NOT to read:** you're trying to learn how the system works, or what the current contracts are. Use the live docs in their proper folders instead.

Each file should carry a `Status:` banner at the top noting its date and that it is not a current reference.
